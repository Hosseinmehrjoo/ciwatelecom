از سیستم‌عامل خام تا اولین زنگ

این صفحه برای کسی است که CIWA را ندیده. هر فصل را به ترتیب انجام دهید. دستورها را همان‌طور که هست کپی کنید و فقط آدرس‌های نمونه را با شبکه خودتان عوض کنید.

زمان تقریبی: ۲ تا ۴ ساعت سیستم‌عامل: Debian 12 یا Ubuntu 24.04 پنل: پورت 8080 تلفن: SIP و Cisco 7942 / 7962

۰۲کلمه‌هایی که در این راهنما می‌آیند

کلمهمعنی عملی
داخلیشماره یک نفر داخل شرکت، مثلاً 101. گوشی با همین شماره و یک رمز روی سرور ثبت می‌شود.
ترانکخطی که سرور را به مخابرات یا شرکت SIP وصل می‌کند. برای تماس داخل شرکت لازم نیست.
SIPزبانی که گوشی با آن زنگ را شروع می‌کند. روی این نرم‌افزار پورت UDP شماره 5060 است.
RTPخود صدا. UDP از 10000 تا 20000. اگر بسته باشد زنگ می‌خورد و صدا نمی‌آید.
TFTPروش گرفتن فایل تنظیم برای Cisco 7942 و 7962. پورت UDP شماره 69.
AMIرابط مدیریت Asterisk برای خود پنل. پورت TCP شماره 5038. فقط روی سرور می‌ماند.
در همه مثال‌ها سرور 192.168.88.10 و شبکه تلفن‌ها 192.168.88.0/24 است. قبل از ذخیره، این دو را با آدرس واقعی شرکت عوض کنید.

اگر سرور مجازی است

کارت شبکه باید Bridge باشد تا گوشی‌ها خود سرور را ببینند. NAT ماشین مجازی برای مرکز تلفن مناسب نیست.

یک آدرس ثابت برای سرور انتخاب کنید که داخل DHCP به دستگاه دیگری داده نشود. در میکروتیک این آدرس را از استخر DHCP خارج کنید، یا یک رزرو بسازید.

۰۴نصب سیستم‌عامل

Debian 12 را نصب کنید. Ubuntu 24.04 Server هم کار می‌کند؛ ساخت Asterisk داخل کانتینر انجام می‌شود و به دسکتاپ نیاز ندارد.

  1. فایل نصب شبکه Debian 12 نسخه amd64 را از debian.org بگیرید.
  2. با Rufus در ویندوز، یا با dd در لینوکس، آن را روی فلش بنویسید و از فلش بوت کنید.
  3. Graphical install را بزنید. زبان نصب را English بگذارید تا اسم گزینه‌ها با این راهنما یکی باشد. کشور را Iran و ساعت را Tehran انتخاب کنید.
  4. نام میزبان را ciwa بگذارید. دامنه را می‌توانید local بنویسید.
  5. برای root یک رمز قوی بگذارید. بعد یک کاربر معمولی بسازید، مثلاً ciwa. رمز این کاربر را جایی امن یادداشت کنید؛ با همین کاربر ادامه می‌دهیم.
  6. دیسک: Guided, use entire disk. این دیسک فقط برای مرکز تلفن است. اگر داده دیگری رویش هست، این گزینه آن را پاک می‌کند.
  7. در انتخاب نرم‌افزار فقط SSH server و standard system utilities را علامت بزنید. محیط گرافیکی نصب نکنید.
  8. نصب که تمام شد فلش را بیرون بیاورید و reboot کنید. با کاربر ciwa وارد شوید.
اگر Debian به کاربر شما sudo نداده، یک بار با root وارد شوید و این دو دستور را بزنید، بعد خارج شوید و دوباره با کاربر ciwa وارد شوید: apt install -y sudo و usermod -aG sudo ciwa.

از این‌جا به بعد همه دستورها را در همین سرور، داخل ترمینال SSH، اجرا کنید. از کامپیوتر خودتان: ssh ciwa@192.168.88.10

۰۵آدرس ثابت و به‌روزرسانی

اول اسم کارت شبکه را ببینید. معمولاً eth0 یا چیزی مثل ens18 است.

ip -br link

Debian

فایل /etc/network/interfaces را با نام کارت خودتان این‌طور بنویسید. اگر کارت ens18 است، همان را به‌جای eth0 بگذارید.

sudo tee /etc/network/interfaces >/dev/null <<'EOF'
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet static
    address 192.168.88.10/24
    gateway 192.168.88.1
    dns-nameservers 192.168.88.1 1.1.1.1
EOF
sudo systemctl restart networking || sudo reboot
اگر Ubuntu 24.04 نصب کرده‌اید

به‌جای فایل بالا، Netplan را بنویسید. نام فایل داخل /etc/netplan/ را با ls /etc/netplan ببینید.

sudo tee /etc/netplan/01-ciwa.yaml >/dev/null <<'EOF'
network:
  version: 2
  ethernets:
    eth0:
      addresses: [192.168.88.10/24]
      routes:
        - to: default
          via: 192.168.88.1
      nameservers:
        addresses: [192.168.88.1, 1.1.1.1]
EOF
sudo netplan apply

بعد از برگشتن شبکه، این‌ها را بزنید. خروجی ip -4 addr باید 192.168.88.10 را نشان بدهد.

sudo apt update
sudo apt full-upgrade -y
sudo timedatectl set-timezone Asia/Tehran
sudo apt install -y curl ca-certificates git

۰۶نصب Docker و Node.js

پنل، پایگاه داده و Asterisk با Docker اجرا می‌شوند. Node روی خود سرور فقط برای TFTP گوشی‌های سیسکو لازم است. اگر سیسکو ندارید، Node را باز هم نصب کنید تا بعداً مجبور به برگشتن نشوید.

sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v
docker --version
docker compose version
عضویت در گروه docker بعد از یک خروج و ورود دوباره به SSH اعمال می‌شود. همین حالا از SSH خارج شوید و دوباره وصل شوید، وگرنه دستورهای بعدی خطای permission می‌دهند.

فایل /opt/ciwa/.env را باز کنید و این مقدارها را بگذارید. رمز پایگاه را یک رشته بلند و تصادفی بگذارید و همان را جای changeme بنویسید.

۰۸ساخت و اجرای Asterisk

این مرحله طولانی است و به اینترنت نیاز دارد. بسته به سرعت سرور بین ۲۰ تا ۹۰ دقیقه طول می‌کشد. پوشه core/asterisk را دستی ویرایش نکنید؛ پنل فایل‌های config/asterisk را می‌سازد.

cd /opt/ciwa
./scripts/install/build-asterisk-docker.sh
./scripts/install/start-asterisk.sh

دستور دوم باید نسخه Asterisk را چاپ کند و این جمله را بدهد: ciwa-asterisk is running. اگر کانتینر همان لحظه بسته شد، آخر لاگ را بخوانید:

docker logs ciwa-asterisk --tail 80

این سرویس با شبکه خود سرور بالا می‌آید، نه داخل شبکه داخلی Docker. به همین خاطر SIP، صدا، سافت‌فون و AMI روی خود ماشین شنیده می‌شوند و با ری‌استارت Docker دوباره برمی‌گردند.

۰۹بالا آوردن پنل، API و پایگاه داده

cd /opt/ciwa
docker compose up -d --build
docker compose ps

سه سرویس باید در حالت running باشند: postgres، api و web. اولین ساخت image چند دقیقه طول می‌کشد.

در مرورگر یک کامپیوتر داخل همان شبکه باز کنید:

http://192.168.88.10:8080
پورت پنل 8080 است. پورت 5173 فقط برای حالت توسعه است و در نصب شرکت استفاده نمی‌شود. پورت 3000 مال این نرم‌افزار نیست.

۱۰ورود و عوض کردن رمز

  1. نام کاربری admin و رمز admin.
  2. همان لحظه رمز را عوض کنید. پنجره تغییر رمز اگر نیامد، از منوی «مدیریت سامانه» رمز مدیر را عوض کنید.
  3. از منوی سیستم، «وضعیت هسته» را باز کنید. اتصال AMI باید برقرار باشد. اگر نبود، یک داخلی آزمایشی ذخیره کنید تا پیکربندی دوباره ساخته شود، بعد docker restart ciwa-asterisk و docker compose restart api را بزنید.

منو چهار گروه دارد: داشبورد، مرکز تلفن، گزارش و مانیتور، سیستم و هسته. نصب را از «سیستم و هسته» شروع کنید، بعد بروید سراغ داخلی‌ها.

۱۲مسیر الف · فقط تماس داخلی

ترانک، مسیر خروجی و مسیر ورودی نسازید. خط شهری در این مسیر وجود ندارد.

  1. منو: داخلی‌ها. دکمه ساخت را بزنید.
  2. شماره داخلی، مثلاً 101. نام نمایشی، مثلاً نام شخص.
  3. نوع گوشی: برای تلفن رومیزی Yealink و مشابه آن «تلفن SIP معمولی». برای 7942 یا 7962 همان مدل سیسکو. برای سافت‌فون داخل پنل «سافت‌فون / WebRTC».
  4. رمز SIP را جدا از شماره انتخاب کنید. این رمز را روی گوشی هم وارد می‌کنید.
  5. ذخیره. برای نفر دوم شماره 102 را همین‌طور بسازید.

از گوشی 101 شماره 102 را بگیرید. هر دو طرف باید زنگ و صدا داشته باشند. اگر فقط زنگ هست، فصل «اگر کار نکرد» را ببینید؛ معمولاً SIP ALG یا بسته بودن RTP است.

صندوق صوتی اگر در فرم داخلی روشن باشد، بعد از تمام شدن مهلت زنگ، تماس بی‌پاسخ به صندوق می‌رود. دکمه پیام گوشی سیسکو در این نسخه یک کد جدا در شماره‌گیری نمی‌سازد.

۴. چیزی که باید از بیرون به سرور برسد

در میکروتیک، UDP پورت 5060 و UDP از 10000 تا 20000 را فقط به 192.168.88.10 فوروارد کنید. پنل، TFTP و پورت 5038 را به اینترنت راه ندهید. در فصل میکروتیک دستور آماده‌اش هست.

در SIP / RTP فیلد «IP خارجی» را برابر آدرس عمومی ثابت شرکت بگذارید. گوشی‌های داخل شبکه هم در این حالت صدا را به همان آدرس عمومی می‌فرستند، پس میکروتیک باید NAT برگشتی (hairpin) داشته باشد. بدون آن، تماس شهری درست می‌شود و تماس داخلی بی‌صدا می‌شود، یا برعکس.

۵. آزمون

  1. از 101 یک موبایل را با صفر اول بگیرید. زنگ و صدای دوطرفه.
  2. از همان موبایل به DID زنگ بزنید. داخلی 101 زنگ بخورد و صدا دوطرفه باشد.
  3. باز هم 101 به 102 زنگ بزند تا مطمئن شوید مسیر شهری، داخلی را خراب نکرده.
کدک گوشی رومیزی و سیسکو در این نرم‌افزار ulaw و alaw است. اگر فروشنده فقط G.729 بخواهد، این نصب آن را پیشنهاد نمی‌کند؛ از فروشنده alaw بخواهید.

۱۵Cisco 7942 و 7962

این دو مدل تنظیم را از صفحه وب نمی‌گیرند. با TFTP فایل SEP و مک‌آدرس خودشان را می‌خوانند. هر دو از خانواده فریم‌ور SIP42 هستند. فریم‌ور باید SIP باشد. اگر گوشی هنوز SCCP است و فقط دنبال Call Manager می‌گردد، تا وقتی فایل‌های SIP را از TFTP نگیرد روی این مرکز ثبت نمی‌شود.

۱. فایل فریم‌ور

بسته SIP42 را که لایسنس آن را دارید داخل /opt/ciwa/tftp/ کپی کنید. نام فایل .loads باید با فیلد «نام فریم‌ور SIP42» در پنل یکی باشد. پیش‌فرض نرم‌افزار این است:

SIP42.9-4-2SR3-1S

کنار آن، فایل‌های .sbn و .loads همان بسته (از جمله term42 برای 7942 و term62 برای 7962) باید در همین پوشه باشند. نرم‌افزار این فایل‌ها را نمی‌سازد و همراه مخزن نیستند.

۲. داخلی در پنل

  1. نوع گوشی را Cisco 7942 یا Cisco 7962 بگذارید.
  2. مک‌آدرس ۱۲ رقمی را بدون دونقطه وارد کنید، مثلاً 001122334455. مک پشت گوشی یا روی برچسب است.
  3. ذخیره کنید. فایل /opt/ciwa/tftp/SEP001122334455.cnf.xml و dialplan.xml ساخته می‌شوند. نام فایل مک را با حروف بزرگ می‌نویسد.
  4. در SIP / RTP، «آدرس سرور برای گوشی سیسکو» باید IP سرور در LAN باشد، نه اسم دامنه و نه IP عمومی.

۳. سرویس TFTP

پورت 69 فقط با دسترسی root باز می‌شود. این واحد systemd را بسازید تا بعد از قطع برق هم بالا بیاید.

sudo tee /etc/systemd/system/ciwa-tftp.service >/dev/null <<'EOF'
[Unit]
Description=CIWA Cisco TFTP
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/ciwa
ExecStart=/usr/bin/node /opt/ciwa/backend/services/asterisk/tftpServer.js /opt/ciwa/tftp 69
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now ciwa-tftp
sudo ss -ulpn | grep ':69'

باید ببینید Node روی 0.0.0.0:69 گوش می‌دهد. لاگ درخواست گوشی: journalctl -u ciwa-tftp -f

۴. DHCP گزینه 150

سیسکو آدرس سرور TFTP را از گزینه 150 می‌گیرد. مقدارش چهار بایت آدرس سرور است، نه متن. برای 192.168.88.10 می‌شود 0xC0A8580A. آدرس خودتان را این‌جا حساب کنید.

۵. ریست گوشی

  1. برق را بکشید. دکمه # را نگه دارید و برق را وصل کنید تا چراغ دکمه‌های خط چشمک بزند.
  2. # را رها کنید و 123456789*0# را وارد کنید. گوشی به تنظیم کارخانه برمی‌گردد و از DHCP گزینه 150 را می‌خواند.
  3. در لاگ TFTP باید درخواست SEP<MAC>.cnf.xml و بعد فایل‌های فریم‌ور را ببینید.
  4. بعد از بالا آمدن، داخلی روی سرور Registered می‌شود. از همان گوشی یک داخلی دیگر را بگیرید.
اگر مک در پنل بعد از بوت گوشی ذخیره شود، گوشی فایل را پیدا نمی‌کند. اول فایل SEP را بسازید، بعد گوشی را ریست کنید. TFTP را به اینترنت باز نکنید.

۱۶سافت‌فون داخل پنل

نوع داخلی را «سافت‌فون / WebRTC» بگذارید. مرورگر باید به پورت TCP شماره 8089 همان سرور برسد. این پورت WebSocket امن Asterisk است و جدا از پنل 8080 است. برای کار روزمره دفتر، تلفن رومیزی کافی است.

۱۷فایروال خود سرور

دو لایه دارید. لایه قابل اعتماد برای دفتر، میکروتیک است، چون جلوی کل شبکه ایستاده. لایه دوم روی خود سرور است و سرویس‌هایی را می‌بندد که مستقیم روی ماشین گوش می‌دهند: SIP، RTP، TFTP، سافت‌فون و AMI.

پنل در منوی فایروال قانون را ذخیره می‌کند و فایل config/ciwa/firewall.nft را می‌سازد. دکمه «اعمال فایروال» داخل کانتینر معمولاً دسترسی root میزبان را ندارد. بعد از چیدن قانون‌ها در پنل، روی خود سرور این را بزنید:

sudo nft -f /opt/ciwa/config/ciwa/firewall.nft
sudo nft list table inet ciwa_filter

در فرم پنل، پروتکل را udp یا tcp بنویسید. منبع را any نگذارید مگر واقعاً لازم باشد. این قانون‌ها برای مسیر داخلی کافی‌اند. منبع را با شبکه خودتان عوض کنید.

پروتکلپورتمنبععملتوضیح
tcp22192.168.88.0/24acceptSSH مدیران
udp5060192.168.88.0/24acceptSIP گوشی‌ها
udp10000-20000192.168.88.0/24acceptصدای تماس
udp69192.168.88.0/24acceptTFTP سیسکو
tcp8089192.168.88.0/24acceptسافت‌فون
tcp5038127.0.0.1acceptAMI فقط خود سرور

سیاست ورودی را drop بگذارید. سیاست خروجی accept بماند. برای مسیر شهری، یک قانون UDP به پورت 5060 اضافه کنید که منبعش فقط IP شرکت SIP باشد، نه کل اینترنت.

Docker پورت 8080 پنل را از زنجیره معمولی ورودی رد می‌کند. بستن 8080 فقط در nft جلوی پنل را نمی‌گیرد. پنل را در میکروتیک محدود کنید. پورت API یعنی 8788 را اصلاً به شبکه نشان ندهید؛ مرورگر از خود 8080 به API می‌رسد. اگر 8788 در docker compose ps روی 0.0.0.0 منتشر شده، در میکروتیک به آن allow ندهید.

این قانون انتشار Docker را به شبکه تلفن محدود می‌کند. نام اینترفیس را اگر eth0 نیست عوض کنید.

sudo iptables -I DOCKER-USER -i eth0 -p tcp --dport 8788 -j DROP
sudo iptables -I DOCKER-USER -i eth0 -s 192.168.88.0/24 -p tcp --dport 8080 -j ACCEPT
sudo iptables -I DOCKER-USER -i eth0 -p tcp --dport 8080 -j DROP

این سه خط تا ری‌استارت بعدی می‌مانند. برای دفتر، همان قانون میکروتیک را دائمی حساب کنید و این را لایه اضافه بدانید.

۱۸فایروال میکروتیک

اول SIP ALG را خاموش کنید. اگر روشن بماند زنگ می‌خورد و صدا خراب می‌شود.

/ip firewall service-port
set sip disabled=yes
/ip firewall address-list
add list=ciwa-pbx address=192.168.88.10 comment="CIWA server"
add list=ciwa-phones address=192.168.88.0/24 comment="IP phones"
add list=ciwa-admins address=192.168.88.0/24 comment="panel users"

اگر چند VLAN دارید، هر رنج را یک خط جدا به ciwa-phones اضافه کنید. قانون‌های زیر را بالاتر از drop عمومی بگذارید.

/ip firewall filter
add chain=forward action=accept connection-state=established,related comment="ciwa established"
add chain=forward action=accept connection-state=new src-address-list=ciwa-phones dst-address-list=ciwa-pbx protocol=udp dst-port=69 comment="ciwa TFTP"
add chain=forward action=accept connection-state=new src-address-list=ciwa-phones dst-address-list=ciwa-pbx protocol=udp dst-port=5060 comment="ciwa SIP"
add chain=forward action=accept connection-state=new src-address-list=ciwa-pbx dst-address-list=ciwa-phones protocol=udp src-port=5060 comment="ciwa SIP reply"
add chain=forward action=accept connection-state=new src-address-list=ciwa-phones dst-address-list=ciwa-pbx protocol=udp dst-port=10000-20000 comment="ciwa RTP to server"
add chain=forward action=accept connection-state=new src-address-list=ciwa-pbx dst-address-list=ciwa-phones protocol=udp src-port=10000-20000 comment="ciwa RTP to phones"
add chain=forward action=accept connection-state=new src-address-list=ciwa-admins dst-address-list=ciwa-pbx protocol=tcp dst-port=8080 comment="ciwa panel"
add chain=forward action=accept connection-state=new src-address-list=ciwa-admins dst-address-list=ciwa-pbx protocol=tcp dst-port=8089 comment="ciwa softphone"
add chain=forward action=drop connection-state=new dst-address-list=ciwa-pbx protocol=udp dst-port=69,5060,10000-20000 in-interface-list=WAN comment="block phone ports from internet"
add chain=forward action=drop connection-state=new dst-address-list=ciwa-pbx protocol=tcp dst-port=8080,8089,8788,5038 in-interface-list=WAN comment="block panel AMI API from internet"
اگر اینترفیس اینترنت داخل لیست WAN نیست، به‌جای in-interface-list=WAN بنویسید in-interface=ether1 با نام واقعی پورت اینترنت. برای مسیر الف هیچ dst-nat نسازید.

فقط وقتی خط شهری دارید

1.2.3.4 را با IP عمومی ثابت شرکت و 203.0.113.10 را با IP سرور SIP مخابرات عوض کنید. 203.0.113.10 فقط نمونه است.

/ip firewall nat
add chain=dstnat action=dst-nat protocol=udp dst-address=1.2.3.4 dst-port=5060 to-addresses=192.168.88.10 to-ports=5060 comment="ciwa SIP"
add chain=dstnat action=dst-nat protocol=udp dst-address=1.2.3.4 dst-port=10000-20000 to-addresses=192.168.88.10 comment="ciwa RTP"
add chain=srcnat action=masquerade protocol=udp src-address=192.168.88.0/24 dst-address=192.168.88.10 dst-port=5060 comment="ciwa hairpin SIP"
add chain=srcnat action=masquerade protocol=udp src-address=192.168.88.0/24 dst-address=192.168.88.10 dst-port=10000-20000 comment="ciwa hairpin RTP"

/ip firewall filter
add chain=forward action=accept connection-state=new protocol=udp dst-address=192.168.88.10 dst-port=5060 src-address=203.0.113.10 comment="SIP only from provider"
add chain=forward action=accept connection-state=new protocol=udp dst-address=192.168.88.10 dst-port=10000-20000 in-interface-list=WAN comment="RTP from calls"
add chain=forward action=drop connection-state=new protocol=udp dst-address=192.168.88.10 dst-port=5060 in-interface-list=WAN comment="drop other internet SIP"

قانون accept مخصوص فروشنده را بالاتر از drop عمومی SIP بگذارید. پورت 8080، 69 و 5038 در dst-nat نیستند و نباید باشند.

۱۹بعد از بالا آمدن

سرویس‌هایی که باید بعد از برق ماندگار باشند

sudo systemctl enable docker
docker update --restart unless-stopped ciwa-asterisk
cd /opt/ciwa && docker compose up -d
sudo systemctl enable ciwa-tftp

اگر سیسکو ندارید، واحد TFTP را enable نکنید.

دیدن ثبت گوشی

docker exec -e LD_LIBRARY_PATH=/opt/ciwa-asterisk/lib ciwa-asterisk \
  /opt/ciwa-asterisk/sbin/asterisk -C /etc/asterisk/asterisk.conf \
  -rx "pjsip show endpoints"

داخلی ثبت‌شده Contact دارد. در پنل هم «مانیتور زنده» هنگام زنگ، تماس را نشان می‌دهد.

پشتیبان

در «مدیریت سامانه» پشتیبان بگیرید. فایل‌های مهم روی دیسک این‌ها هستند: /opt/ciwa/config، /opt/ciwa/.env، /opt/ciwa/storage و حجم Docker پایگاه. کپی گرفتن از کل /opt/ciwa به‌اضافه docker compose برای یک دفتر کوچک کافی است. رمزها داخل همین پوشه‌اند؛ نسخه پشتیبان را مثل یک رمز عبور نگه دارید.

امکان‌هایی که بعد از تماس اول اضافه می‌کنید

  • صف تماس: یک شماره ورود، استراتژی ringall، و عضوهایی مثل 101,102.
  • IVR: منوی صوتی. گزینه‌ها را به شکل JSON می‌دهید، مثلاً رقم 1 به داخلی 101.
  • گروه زنگ: یک شماره که همزمان چند داخلی را زنگ می‌زند.
  • زمان‌بندی: ساعت اداری و مقصد خارج از ساعت.
  • کنفرانس: یک شماره ورود و در صورت نیاز یک پین.
